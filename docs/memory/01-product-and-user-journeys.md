# 产品定位与用户旅程

## 产品判断

NanZi 最适合定位为：**可嵌入、可追溯、基于企业真实数据和知识执行任务的可信业务智能体平台**。

项目的差异化资产是 ChatBI 证据闭环、知识引用、资源权限、报表订阅、个人工作台和场景交付，而不是再做一个通用聊天壳或完整复制 Dify、Coze、n8n 的所有能力。

## 用户与价值

| 用户 | 主要任务 | 当前产品入口 |
|---|---|---|
| 业务员工/经理 | 提问、处理待办、继续工作、查看报表 | 工作台、智能助手、数据门户、任务 |
| Agent 构建者 | 配置、调试、发布智能体 | Agent、Prompt、Skills、MCP、Debug |
| BI/数据运营 | 建设可信数据语义层 | 数据源、Profiling、元数据、指标、案例集 |
| 知识运营 | 管理文档并改善召回质量 | 知识中心、文档、检索 A/B、运营指标 |
| 管理员/安全人员 | 管理身份、权限、额度和审计 | 用户、角色、系统配置、审计、Token |
| 集成开发者 | 把智能体嵌入业务系统 | iframe Embed、V1 API |

## 主要业务旅程

```text
员工：登录 -> 工作台 -> 待办/最近产出 -> 继续会话、任务或报表 -> 反馈
构建者：创建 Agent -> 绑定模型/工具/Skill -> 调试 -> 创建版本 -> 发布 -> 查看执行记录
数据运营：连接数据库 -> Profiling -> 导入元数据 -> 配置指标/关系 -> 授权 -> 验证 ChatBI
知识运营：创建知识库 -> 上传/解析 -> 检索测试 -> 绑定 Agent -> 检查引用和召回指标
场景负责人：选择模板 -> 绑定依赖 -> 预检 -> 安装 -> 验收问题 -> 正式交付
集成开发者：加载 iframe -> 握手/注入上下文 -> SSE 对话 -> 接收宿主事件
```

## 已有优势

- 个人工作台围绕待处理工作、运行中任务和最近产出组织，不是空白聊天框。
- 场景安装包含依赖选择、预检、验收问题和交付清单。
- 数据门户、保存报表、订阅和通知形成了分析到业务交付的闭环。
- Agent 草稿/版本、知识检索测试和 Skill 发布已经具备治理雏形。
- Embed 支持主题、专家直选、上下文、会话恢复和宿主事件。

## 产品缺口

| 问题 | 影响 | 建议 |
|---|---|---|
| 侧栏约 24 个入口、个人中心 9 个 Tab | 认知负担过高 | 拆分普通用户、构建者、管理员三类工作区 |
| 场景市场和数据门户入口隐藏 | 差异化能力难发现 | 提升为一级入口 |
| 缺少统一评测与发布中心 | 发布质量依赖人工调试 | 评测集、评分器、质量门禁、灰度和回滚 |
| 场景模板硬编码在 Python | 无法运营、审核和升级 | 数据库/包格式场景资产中心 |
| 没有正式租户模型 | 多租户声明超过实现 | `tenant_id`、强制查询过滤、租户密钥/额度/审计 |
| 缺少业务结果指标 | 无法证明平台价值 | 任务成功、采纳、节省时间、质量和 ROI |
| 工作流能力有限 | 难以承载确定性业务流程 | 条件、并行、审批、补偿和幂等节点 |

## 推荐信息架构

| 工作区 | 一级导航 |
|---|---|
| 普通用户 | 工作台、智能助手、数据门户、任务、我的资源 |
| 构建者 | Agent、场景、数据、知识、工具、评测 |
| 管理员 | 用户与权限、运行治理、系统设置 |

## 产品验收原则

1. 基于企业数据或知识的回答必须展示证据、时效和权限上下文。
2. 有副作用的工具必须支持审批、幂等和执行回执。
3. 发布的 Agent 版本必须带评测证据，并支持回滚。
4. 场景包必须声明依赖、权限、验收用例和升级兼容性。
5. 北极星指标应是“被用户接受的成功业务任务数”，而不是消息或 Token 数。
